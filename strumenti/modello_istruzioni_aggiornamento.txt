LA REGOLA
 Ogni aggiornamento va PRIMA nella copia di prova:  cartella /opt/lampp/htdocs/mydibest_pp   indirizzo https://dibest2.unical.it/mydibest_pp
 Solo se li' va tutto bene, si carica nel sito vero:  cartella /opt/lampp/htdocs/mydibest
 Si usa lo STESSO file .tgz tutte e due le volte. Se il tempo 1 va male, il sito vero non e' stato toccato.

COSA C'E' NEL PACCHETTO
 Tutto il codice del portale, con l'elenco di controllo SHA256SUMS_pacchetto.txt. NON ci sono: .env, uploads, cache, backups, il .htaccess della radice.
 Quindi il .env, i file caricati e la cache (sia della copia sia del sito vero) non vengono mai toccati.
 I file che non esistono piu' nel codice nuovo restano sul server (il pacchetto aggiunge e sostituisce, non toglie).
 Se in questo aggiornamento e' cambiato il .htaccess della radice, NON e' nel pacchetto: va messo a mano, prima nella copia e poi nel sito vero.
 SCHEMA DEL DATABASE: non si lancia nessun comando SQL. Si aggiorna da solo al primo accesso a una pagina del pannello (nella copia PRIMA: e' la prova che funziona).

TEMPO 1 - LA COPIA DI PROVA (entra sul server con ssh dodaroe@160.97.37.188)

 1) Aggiorna SOLO il codice della copia (non tocca .env, uploads, cache, database):

    controlla che il .env non si legga dal web e che la pagina abbia la fascia arancione.
    Deve finire con "CODICE DELLA COPIA AGGIORNATO". Se finisce con un ERRORE la copia e' IN PAUSA (il .env diventa .env.sospeso):
    NON passare al tempo 2. Rifai il pacchetto e rilancia lo stesso comando: la copia riparte da sola se tutto va bene.
 2) Apri nel browser una pagina del pannello: https://dibest2.unical.it/mydibest_pp/admin/  (accedi con il tuo accesso di Ateneo).
    Al primo accesso lo schema del database si aggiorna da solo. Se compare un errore, fermati e scrivimelo.
 3) (Facoltativo) Se servono dati piu' freschi del sito vero, PRIMA delle prove:
      sudo bash ~/crea_ambiente_prova.sh aggiorna-dati --anonimizza
 4) PROVE A MANO (solo dati di prova, mai dati veri). Sempre:
      - in cima a ogni pagina c'e' la fascia arancione "AMBIENTE DI PROVA"
      - le email partono solo verso l'indirizzo di prova, con [PROVA] nell'oggetto
      - il pannello si apre senza errori
    E poi le prove di questo aggiornamento:

 5) Verifica automatica dall'esterno (dal tuo computer, dentro la rete di Ateneo):

TEMPO 2 - IL SITO VERO (solo se il tempo 1 e' andato bene in ogni sua parte)
 Imposta la data una volta (serve per i nomi delle copie di sicurezza):
      DATA=$(date +%Y%m%d_%H%M)
 A) Copia di sicurezza del DATABASE (il nome del database e' DB_NAME nel .env:
    per vederlo senza stampare la password:  grep '^DB_NAME' /opt/lampp/htdocs/mydibest/.env )
      sudo mysqldump --single-transaction --no-tablespaces NOME_DATABASE | gzip > ~/db_prima_aggiornamento_$DATA.sql.gz
      gzip -t ~/db_prima_aggiornamento_$DATA.sql.gz && ls -lh ~/db_prima_aggiornamento_$DATA.sql.gz
    (il file deve essere grande, non 0 byte; senza --events e --routines)
 B) Copia di sicurezza dei FILE che stai per sostituire (i file nuovi non ci sono ancora: l'avviso di tar e' normale)
      cd /opt/lampp/htdocs/mydibest
      tar tzf ~/aggiornamento_completo.tgz | grep -v '^SHA256SUMS_pacchetto.txt$' > ~/elenco_file_$DATA.txt
      tar czf ~/backup_file_prima_$DATA.tgz --ignore-failed-read -T ~/elenco_file_$DATA.txt
 C) Estrai il pacchetto nel sito vero (l'elenco di controllo va nella tua cartella, non nel portale)
      tar xzf ~/aggiornamento_completo.tgz -C /opt/lampp/htdocs/mydibest --exclude=SHA256SUMS_pacchetto.txt
      tar xzf ~/aggiornamento_completo.tgz -C ~/ SHA256SUMS_pacchetto.txt
 D) Controlla che nessun file manchi o sia diverso (non deve stampare nessun errore e deve finire con TUTTO_OK)
      cd /opt/lampp/htdocs/mydibest && sha256sum -c --quiet ~/SHA256SUMS_pacchetto.txt && echo TUTTO_OK
 E) Controlla la sintassi con il PHP del server (non deve stampare nessuna riga di errore; alla fine stampa FINE_CONTROLLO)
      cd /opt/lampp/htdocs/mydibest && for f in $(awk '{print $2}' ~/SHA256SUMS_pacchetto.txt | grep '\.php$'); do /opt/php84/bin/php -l "$f"; done | grep -v '^No syntax errors'; echo FINE_CONTROLLO
 F) Permessi: i file devono essere leggibili dal web
      cd /opt/lampp/htdocs/mydibest && awk '{print $2}' ~/SHA256SUMS_pacchetto.txt | xargs chmod 644
 G) Classi nuove (autoload): il portale le trova da solo con src/autoload.php, se sul server NON c'e' la cartella vendor.
    Controllo (deve rispondere "niente vendor"):
      test -f /opt/lampp/htdocs/mydibest/vendor/autoload.php && echo "C'E' vendor: dimmelo" || echo "niente vendor: va bene"
    Se risponde "C'E' vendor", guarda se l'autoload e' "autoritativo" (in quel caso le classi nuove non si troverebbero):
      grep -n "setClassMapAuthoritative(true)" /opt/lampp/htdocs/mydibest/vendor/composer/autoload_real.php
    Se quel comando stampa una riga, serve:  cd /opt/lampp/htdocs/mydibest && composer dump-autoload   (altrimenti niente)
 H) OPcache si rinfresca da solo in circa 1 minuto. Per averlo subito (comando da amministratore, lo incolli tu):
      sudo systemctl reload php84-fpm
 I) Apri una pagina del pannello del sito vero (https://dibest2.unical.it/mydibest/admin/): al primo accesso lo schema si aggiorna da solo.
 J) Prove brevi, uguali a quelle fatte nella copia (stavolta senza fascia arancione e con le email vere: usa solo dati di prova, mai dati veri) e verifica dall'esterno:
      bash strumenti/verifica_sito.sh https://dibest2.unical.it/mydibest

RITORNO INDIETRO NEL SITO VERO (se qualcosa non va)
      cd /opt/lampp/htdocs/mydibest && tar xzf ~/backup_file_prima_$DATA.tgz
   poi togli i file nuovi che prima non c'erano (questo elenco li mostra: sono i file del pacchetto che non sono nella copia di sicurezza):
      tar tzf ~/backup_file_prima_$DATA.tgz | sort > ~/gia_presenti_$DATA.txt; sort ~/elenco_file_$DATA.txt | comm -13 ~/gia_presenti_$DATA.txt -
      (controlla l'elenco, poi togli a mano i file che compaiono con:  rm -f /opt/lampp/htdocs/mydibest/PERCORSO )
   Il database si ripristina solo se lo schema e' cambiato o i dati sono stati rovinati:
      gunzip -c ~/db_prima_aggiornamento_$DATA.sql.gz | sudo mysql NOME_DATABASE      (CANCELLA le modifiche fatte dopo la copia: chiedimi prima)
   Se $DATA non c'e' piu' (hai chiuso la sessione), guarda i nomi con:  ls -t ~/backup_file_prima_*.tgz ~/db_prima_aggiornamento_*.sql.gz | head
